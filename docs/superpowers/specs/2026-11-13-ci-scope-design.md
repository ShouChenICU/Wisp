# CI 验证范围设计

用户已批准按风险精简日常检查，保留完整发布检查。

- 日常检查始终执行格式、分层、资源预算、翻译一致性、生成文件一致性、构建和 C++ 回归测试。
- 模拟器日常覆盖启动、外设缺失降级、网络、场景运行与错误处理、Agent 对话；完整检查运行原有全部冒烟场景。
- 工具自测按工具及输入文件的变化选择；无法确定比较基线时运行全部。检查脚本或依赖变化同样运行全部。
- 布局覆盖屏幕形状和语言，纯手势仅覆盖形状。截图预览显式手动运行。
- 不为缩短 CI 修改产品定时逻辑，也不删除存储恢复、线程约束、安全和超时行为的回归检查。
- PR 和功能分支使用日常检查，main 和手动发布检查使用完整模式。
- UI 树折叠、长度上限由纯单元测试覆盖，不在 CI 渲染 2000 控件做墙钟性能基准；场景删除的业务检查直接复用长按动作，保留基础触控长按覆盖，避免重复模拟计时手势。

## 交付前自查

- 自动化检查之外，实施者应主动推敲方案、检查完整受影响流程和同类用法，自行处理范围内的细节缺陷，避免依赖用户反复发现问题。
- UI 修改检查实际渲染、间距、内边距、对齐、换行、触控滚动与相关空态/加载/错误/禁用状态；逻辑修改按影响检查不变量、边界、失败取消、异步生命周期、持久化和资源开销。
- 自查发现的问题在交付前解决；验证依据风险选择，保留必要边界而不扩张无关组合。明确区分已验证结果、假设及仍需设备实测的内容。具体约定同步于 `AGENTS.md` 第 7 节与 `CONTRIBUTING.md`。
