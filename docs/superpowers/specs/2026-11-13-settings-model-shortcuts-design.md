# 设置页快捷模型、Wi-Fi 管理与编译期浅睡开关

状态：全部范围与实施计划已获用户批准；功能已实现，主机验证与圆屏固件编译通过，待真机验收。验证记录见对应实施计划。

## 1. 目标与范围

设备设置页移除“省电睡眠”，浅睡策略默认开启，调试时可在编译期关闭；设备设置页增加已有模型配置的测试、激活入口。新增、编辑、删除模型配置及获取模型列表仍在网页管理后台完成。Wi-Fi 使用独立子页管理，支持开关和手动选网；外接电源时不因待机自动断网。

本设计修订 MVP spec 6.4 的设置页和 scene-device spec 4.1 的浅睡设置约定；模型配置继续遵循 connectivity-admin spec 5.3，不改变其存储格式、测试语义或按类型激活的规则。

## 2. 浅睡改为编译选项

- 提供统一 CMake 选项 `WISP_ENABLE_LIGHT_SLEEP`，默认 `ON`，固件和模拟器均支持以 `-DWISP_ENABLE_LIGHT_SLEEP=OFF` 关闭。构建层向 PowerManager 传入编译结果，可移植层不包含 `sdkconfig.h`。
- 删除设备设置页、网页系统设置、SystemSettings 读写字段及相关 Agent/Lua 设置说明中的 `light_sleep` 动态选项。旧设备持久化的 `power/light_sleep` 不再读取，不影响新策略，也无需专门写 flash 清理。
- 默认开启表示允许 PowerManager 在深度待机且无 CPU 唤醒锁时开启浅睡；亮屏、离开深度待机、持有 CPU 锁时仍关闭实际浅睡。自动熄屏和深度待机时间继续可设置。
- 编译关闭时仍可进入深度待机、关闭 Wi-Fi，但不会请求开启浅睡。不支持浅睡的平台保持现有降级行为。
- `/system/power` 保留浅睡实际状态用于诊断，不提供运行时开关。

## 3. 设备端快捷模型设置

### 3.1 页面

设置页在“网络”后增加“模型”分组，包含“对话”“语音识别”“语音合成”三个入口，分别显示当前激活配置名称；未配置时显示“未配置”。

点击某一类进入同一套子页框架，列出该类型已保存的配置：

- 每项显示配置名称、模型名与当前激活标记；同一服务商的多套配置分别列出，以配置 ID 区分。
- 每项提供“测试连接”和“设为当前”。当前项显示“当前使用”，不重复提交激活操作。
- 测试中显示进度状态并阻止重复操作；成功显示连接成功和延迟，失败显示本地化错误类别。这里的测试与网页现有测试一致，是配置的连接/模型列表探测，不宣称已完成对话或语音推理。
- 测试不自动激活，激活不强制先测试；两项操作各自给出结果。激活失败保持原来的当前项。
- 页面说明“新增或编辑配置，请打开网页管理后台”，显示可换行的后台地址。无配置时显示空状态和同样的引导。

沿用已有页面的返回导航和布局规则；矩形、圆角矩形、圆形屏均可完整操作。长名称和模型名使用分行或省略，不能挤掉操作按钮。中、英、日文同步。

### 3.2 服务、线程与状态

- 使用 `ModelProfileService::get()`、`test(id)`、`activate(id)`，不另建配置存储，也不经设备内部 HTTP 调自己的 REST API。
- 列表来自不含密钥的服务快照；设备页面不接触 Key，不显示服务端原始响应或包含凭据的错误文字。
- 测试网络请求在后台执行，不能阻塞 UI 线程，也不能占用唯一 flash 工作线程等待网络。激活及涉及持久化的工作遵循 StorageWorker 约束。结果只经 `UiRuntime::post()` 更新界面。
- 离开页面、语言重建或重复进入后，旧请求不能访问失效页面，也不能把结果写进新的页面；拒绝提交任务时恢复按钮并显示失败。
- 打开页面及配置变化后刷新服务快照，网页修改或删除配置后设备页面同步更新。执行中配置被删除时按服务错误处理；激活标记以服务实际状态为准。
- 只改变对应类型后续请求使用的配置，不中断已经发出的对话或语音请求。

- UI/接线测试覆盖按类型列表、当前项、空列表、测试成功/失败/忙碌/提交失败、激活成功/失败、网页配置变化，以及离页后异步完成的生命周期。
- 模拟器使用本地假模型服务验证测试与激活，无需外网；检查矩形、圆角和圆形三种屏形，以及三种语言。
- 运行格式、分层、构建、测试和相关网页本地化检查，提交前运行 `bash tools/ci.sh`。

## 5. 兼容性

`light_sleep` 从系统设置契约删除，旧客户端继续提交该字段会按未知字段返回错误，需要更新客户端；诊断状态字段不受影响。其余配置数据不迁移。此次包含功能变化，后续合并发布时应递增 minor 版本，具体发布操作单独遵循用户指令。

## 6. Wi-Fi 专属子页

设置页的 Wi-Fi 行改为打开独立子页，显示当前开关状态与连接摘要，不再直接启动热点。

- 顶部为 Wi-Fi 开关，默认开启；用户选择持久化，重启后保留。关闭即停止连接和配网热点、关闭无线电，保留已保存网络及密码。关闭期间不扫描、不重连，唤醒、插电、后台联网窗口或配网请求不能绕过这个选择。
- 开启后恢复自动连接已保存网络；子页显示当前 SSID、连接中/已连接/失败、IP 和信号状态。
- 显示已保存网络及扫描发现的附近网络，标记当前连接、已保存、是否加密和信号强度，提供刷新扫描。扫描在后台执行，页面保持可操作；关闭 Wi-Fi 后的过期扫描结果不能重新打开或连接网络。
- 点击已保存网络使用保存的凭据连接；密码错误时可重新输入。点击未保存的加密网络打开设备键盘输入密码，开放网络无需密码，提交后保存并连接。输入取消不写入；密码隐藏显示，不进入日志、事件或截图测试产物。连接失败保留可理解的原因并允许重试。
- 保留“通过手机配网”入口，复用现有热点二维码流程；Wi-Fi 关闭时需先显式开启。无 Wi-Fi 设备时显示不可用，不提供无效开关。
- 网络扫描、连接及持久化统一调用 `WifiService`，页面不直接调用 HAL。服务扩展用户启停状态，统一计算用户意愿与省电策略的有效无线电状态；持久化沿用 `net/wifi.json` 原子写入机制，旧文件缺省为开启。
- 所有异步操作遵循第 3.2 节的线程、离页生命周期和 UI 更新约束；中英日文、圆屏和方屏同步支持。

## 7. 插电保持网络

- 以具备 `charging_status` 能力的 Power 设备报告的 `usb_present` 判断外接电源，不能只用 `charging`，否则充满后会误断网。
- 用户开启 Wi-Fi 且插电时，应用持有一把具名 `network` 唤醒锁，沿用现有 PowerManager 规则阻止进入会关闭 Wi-Fi 的深度待机。自动熄屏及普通待机照常进行，不强制保持屏幕点亮。
- 深度待机中插电时取得该锁，回到普通待机并恢复网络，不亮屏；拔电或手动关闭 Wi-Fi 时释放该锁。拔电后按已有空闲时间和其他唤醒锁重新评估省电级别，不人为刷新活动时间。
- 首次供电采样也必须应用策略，不能只监听 `power.charging.changed`，因为现有 PowerMonitor 首次采样不发布变化事件。事件丢失后通过后续状态采样恢复一致。
- 无供电检测能力或采样未知时保持既有电池省电策略，不猜测是否插电。自动保网仅阻止省电断网，不保证路由器或网络服务一直可达，也不覆盖用户主动关闭 Wi-Fi 或关机。
