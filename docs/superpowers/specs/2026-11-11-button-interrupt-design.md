# 按键中断优先与熄屏唤醒设计

- 日期：2026-11-11
- 状态：待用户审阅
- 范围：统一 `ButtonService` 的输入策略：按键可提供中断事件时优先使用中断；仅不支持中断的按键使用轮询，并按亮屏/熄屏状态切换轮询策略。
- 板级依据：Waveshare ESP32-S3-Touch-AMOLED-1.75C 官方原理图显示 PWR 键同时连接 AXP2101 的 PWRON 和 T1 MOSFET 栅极；T1 漏极经 SYS_OUT 接 ESP32-S3 GPIO3。GPIO3 信号极性及启动采样行为须在实板验证。

---

## 1. 背景与目标

当前 `wisp::core::ButtonService` 用一个周期 `os::Timer` 轮询注册的全部按键：默认 20 ms，`PowerManager` 进入 Standby 后统一放宽到 50 ms。圆屏 1.75C 的 `button.power` 使用 `EspPmuPowerKey`，每次 `pressed()` 都通过 I2C 读取 AXP2101 的 PWRON 中断状态寄存器。因此，即使按键没有动作，待机期间按钮服务仍每 50 ms 唤醒并读取一次。

用户已确认希望采用统一的中断优先策略：

1. 按键设备能够发出中断事件时，按键服务使用该事件；不为它周期轮询。
2. 不支持中断的按键才回退轮询。亮屏时使用正常轮询；熄屏后停止普通非中断按键的轮询。
3. 若 PWR 按键在某板上确实无法接入中断，熄屏时该 PWR 回退轮询间隔为 100 ms，以保留电源键唤醒能力。
4. 圆屏 1.75C 在 GPIO3/SYS_OUT 电平与启动约束验证通过后，PWR 键改由 GPIO3 检测，不再为按键读取 AXP2101 PWRON IRQ 状态寄存器。
5. PMU 电源状态采样不因按键输入策略改变：亮屏 1 s、熄屏 30 s，继续提供电池、充电和 VBUS 状态。

目标是消除中断按键造成的周期轮询唤醒；这不等于整机不再有任何周期唤醒。电量监控、电源管理、网络服务及其他定时任务仍可能在其自身期限到达时唤醒系统。

## 2. 非目标

- 不改自动浅睡/深度待机的电源状态机和用户设置语义。
- 不关闭 AXP2101，不停止 PMU 的电量、充电、VBUS 状态采样。
- 不在本期支持深睡（deep-sleep）按键唤醒；设备日常待机仍为自动浅睡。
- 不改变按键设备 id、事件 topic、短按/长按事件名称及 TalkKey/PowerKeyController 的行为契约。
- 不把 GPIO3 用于其他外设，也不自动改变 BOOT 键功能。

## 3. 按键输入模型

### 3.1 中断能力

`hal::Button` 增加可选的事件输入能力。设备须显式声明输入模式：

- **EdgeEvent**：设备能报告按下/松开边沿，并可在熄屏自动浅睡期间作为唤醒源；
- **PollOnly**：只提供当前电平 `pressed()`，由 `ButtonService` 按轮询策略读取。

中断回调不得直接执行 `EventBus::publish()`、分配内存、拿普通互斥锁或运行应用逻辑。平台 ISR 只把固定大小的边沿记录（设备索引/边沿/由 ISR-safe 单调时钟取得的事件时间）写入有界 ISR 安全通道并唤醒按键服务；`ButtonService` 在线程上下文完成消抖、状态转换、事件发布和长按计时。时间戳记录实际边沿时刻，确保同一服务调度间隔内成对到达的按下/松开仍可正确区分短按/长按。边沿记录必须保留，不能只在服务醒来时重新读一个电平而丢失短按。

ISR 安全通道由 `wisp_os` 提供可移植接口，ESP 实现采用 ISR-safe 的有界队列/通知；队列使用固定容量和内部 RAM 可达的存储，不在 ISR 内分配。模拟器实现提供可确定驱动的等价边沿输入，以便主机测试不依赖 GPIO。

### 3.2 事件与手势语义

所有模式统一保留当前公开事件顺序与语义：

- 去抖确认按下后发 `down`；
- 按住达到 `long_press_ms` 时发一次 `long`；
- 松开时发 `up`，若该次按压未触发 `long`，随后发 `short`。

中断边沿的去抖在普通任务上下文用单次延迟确认，不靠固定周期轮询。默认稳定窗口为 20 ms（与当前亮屏按键采样分辨率一致）；若窗口内出现反向边沿则取消该次候选转换。持续按住通过一次性长按期限唤醒服务；长按计时从去抖确认的按下时刻开始。重复/抖动边沿不能产生多组短按，也不能重复触发长按。队列溢出须计数并记录受限告警；服务须重新读取受影响设备的当前电平进行状态恢复，不能静默卡在“按下”状态。

### 3.3 轮询回退

- `PollOnly` 按键亮屏时按当前服务周期轮询（默认 20 ms）。
- 进入 Standby 后，除 `button.power` 以外的 `PollOnly` 按键停止轮询；这些按键在熄屏时不保证唤醒设备。
- `button.power` 若为 `PollOnly`，Standby 与 DeepStandby 下轮询间隔为 100 ms；亮屏后恢复原来的 20 ms 周期。
- 当没有需轮询按键、没有待处理去抖和长按期限、也没有边沿事件时，按键服务阻塞等待事件，不保留周期定时器。
- `PowerManager` 的屏幕状态转换须原子地更新按键服务的活动模式，避免刚进入熄屏时仍重建 50 ms 的全局轮询定时器。

GPIO3 验证通过的圆屏 PWR 按键属于 `EdgeEvent`，因此该板不触发 100 ms PWR 回退轮询。

## 4. 组件与数据流

| 单元 | 变化 |
|---|---|
| `wisp_hal` `Button` | 声明输入模式并提供边沿订阅/注销接口；沿用 `pressed()` 作为启动状态检查和 PollOnly 回退接口。接口不暴露 ESP-IDF 类型。 |
| `wisp_os` | 新增 ISR-safe、有界、固定记录的事件队列/唤醒原语；ESP ISR 只调用其 ISR-safe 操作，模拟器提供可测试实现。 |
| `wisp_core` `ButtonService` | 统一管理中断与轮询按键；一个 `wisp.button` 工作任务阻塞等待边沿、回退轮询期限和最近的长按/消抖期限；在普通任务上下文发布既有事件。不得为每个按键另建任务。 |
| `wisp_port_esp` GPIO button | `EspGpioButton` 可选择边沿模式，ISR 产生边沿记录；睡眠时注册对应 GPIO 的浅睡唤醒电平。 |
| `wisp_port_esp` PMU button | 保留 `EspPmuPowerKey` 作为无 GPIO 板的 PollOnly 回退；其 AXP2101 IRQ 寄存器读取按亮/熄屏间隔执行。 |
| `PowerManager` | 不再对所有按键全局设置 50 ms 周期；Standby/Active 只通知 ButtonService 切换轮询策略。 |
| 圆屏 1.75C `board.cpp` | GPIO3/SYS_OUT 经验证后注册为 `button.power` 的边沿设备；不同时注册同一实体的 PMU 轮询按键。 |

按键服务工作任务只处理内存和事件，声明 `flash_access=false`。其栈不得放入 hot stack；ISR 通道的内部 RAM 用量须在目标板复测。若新增工作任务导致内部 RAM 预算不满足，应改进实现/存储策略，不得修改 `ram_budget.hpp` 来掩盖回归。

## 5. 圆屏 GPIO3/SYS_OUT

原理图中 PWR 按钮节点接 AXP2101 PWRON，并经 R12 驱动 BSS138 栅极；T1 漏极由 R9 上拉到 VCC3V3，网络 SYS_OUT 接 ESP32-S3 GPIO3。按图推测，按键按下拉低栅极使 T1 截止、SYS_OUT 上升；释放后栅极由 PWRON 拉高使 T1 导通、SYS_OUT 下降。此极性只是原理图推导，不视为已在实板测得。

GPIO3 是 ESP32-S3 启动绑带脚。将其用于按键前必须确认：

1. 实板上松开/按下/释放期间 GPIO3 电平与预期一致，包含上电和复位采样；
2. 按住 PWR 上电不会改变固件启动模式或 USB-JTAG 使用；
3. GPIO3 高电平唤醒配置不会造成电平持续时反复进入/退出浅睡；
4. 中断注册、GPIO 睡眠唤醒和已有 GPIO0 BOOT/TalkKey 可同时正常工作。

若 GPIO3 验证失败，圆屏 PWR 回退为 PollOnly，并按本设计的 100 ms Standby 策略运行；不得静默沿用错误的极性或宣称中断已经验证。

## 6. 电源状态与低功耗边界

GPIO 中断配置在 Active、Dim、Standby 与 DeepStandby 间随按键服务的输入状态维持。自动浅睡由现有 ESP-IDF PM 状态机进入；GPIO3 有效电平是浅睡唤醒源。若有效电平在唤醒后仍保持，按键服务必须先锁存并处理该按压、等待确认释放，再允许下一次自动浅睡；不得在同一按住电平下形成反复“浅睡—立即唤醒”。边沿 ISR 只投递记录并设置轻量 wake-pending 标志，不直接操作 LVGL、发布应用事件或执行 PowerManager 转换。按键服务在普通任务上下文消抖并投递既有 `button.power.down`/`up` 事件；`PowerManager` 仍按现有 UI 线程路径点亮屏幕。

采用 EdgeEvent 的按键不会使 ButtonService 每 20/50 ms 唤醒。整机仍可能被以下任务/期限唤醒：PowerManager 周期 tick、电池监控（亮屏 1 s/熄屏 30 s）、网络处理、正在运行的系统计时器或其他唤醒锁。功耗验收只归因于按键服务不再制造周期轮询，不承诺绝对零唤醒。

## 7. 错误处理与兼容性

- 中断初始化失败、工作任务或 ISR 通道资源创建失败时，将该按键降级为 PollOnly 并记录一次警告；若按键是 `button.power`，熄屏采用 100 ms 回退，其他按键遵循熄屏暂停策略。若回退资源也无法创建，按键服务必须上报启动失败；不得静默留下不能唤醒的电源键。
- ISR 通道过载时不做阻塞；设置溢出标记，普通任务恢复状态并记录告警。事件队列大小通过按键数量和最坏边沿突发评估，设备验收确认不会产生持续溢出。
- GPIO 的按下、松开边沿及长按阈值须维持现有工具/事件消费者兼容。BOOT 键仍携带 `role: talk`。
- `PowerMonitor` 采样周期保持亮屏 1 s、熄屏 30 s；GPIO 中断化不移除 PMU 电量、充电或 VBUS 采样。

## 8. 测试与验收

### 8.1 主机测试

- EdgeEvent：按下/松开、边沿在 worker 调度前成对到达仍产生短按、长按恰好一次、持续按住、消抖、重复边沿。
- PollOnly：亮屏 20 ms 回退；进入熄屏普通 fallback 停止；非中断 `button.power` 熄屏 100 ms；唤醒后恢复亮屏周期。
- 混合设备：EdgeEvent 与 PollOnly 并存时，EdgeEvent 不触发轮询读取，fallback 不阻塞事件按键处理。
- 缺失/创建失败、ISR 队列满、设备在运行中注销/析构、熄屏/唤醒并发时不死锁、不 use-after-free，电源键按定义降级。
- 验证按键活动仍遵循现有 `PowerManager` 唤醒行为，且 BOOT/TalkKey 的 press/long/release 语义不变。
- `PowerMonitor` 的 1 s/30 s 周期及采样事件不受按钮调度方式影响。

### 8.2 圆屏设备验证（须在实现后执行）

1. 测量 PWR 键松开、按下、释放和长按期间 GPIO3 的电平/边沿；同时测试复位/上电时按住 PWR，确认启动及 USB-JTAG 正常。
2. 确认 GPIO3 高电平可从自动浅睡唤醒；按住期间不出现反复浅睡/立刻唤醒，松开后可重新进入浅睡。
3. 按下短按/长按 PWR、按住不放、按 BOOT 说话，核对事件顺序、响应延迟和功能。
4. 熄屏待机观察 `sleep` 统计，不再呈现由 50 ms 按键轮询造成的固定短睡眠节奏；同时确认 30 s PMU 状态采样仍生效。
5. 用 `mem` 对比实施前后 idle 与最坏工作集内部 RAM，记录新增任务/ISR 队列的资源；满足 AGENTS.md 与 `ram_budget.hpp` 的既定预算。

## 9. 方案比较与裁定

### 方案 A：统一事件驱动，推荐

在 `wisp_os` 提供 ISR-safe 有界边沿通道，`ButtonService` 用一个阻塞式工作任务统一处理所有按键事件、回退轮询和手势期限。优点是满足全板统一策略、可在没有回退按键时停止按键轮询，并可由模拟器测试。代价是新增一个低优先级非 flash task、一个小型 ISR 通道以及对 HAL/ButtonService 生命周期的改造；需在实板验证内部 RAM、GPIO3 绑带电平和睡眠唤醒。

### 方案 B：仅在圆屏 PWR 上特例化 GPIO3

圆屏通过专门的回调/中断处理 PWR，其他按键继续由现有 ButtonService 定时轮询。代码较少，但 GPIO0 BOOT 仍每 50 ms 造成唤醒，无法满足“按键服务统一优先使用中断”与“所有中断按键不轮询”的目标，不推荐。

### 方案 C：只降低轮询频率

保留当前轮询服务，按键熄屏周期调慢。改动最少但不能消除所有按键的周期唤醒，也不能提供中断优先模式，不符合已确认目标，不采用。
