## 1. 背景、范围与架构

### 1.1 背景

2026-11-06，用户要求尽快看到能用的产品，细节优化放到以后迭代。用户对 MVP 的定义是"包括主界面的完整能独立使用的"设备。本文把子项目 4（4a）、5、6、8 中 MVP 必需的部分合成一份设计，用一份实施计划、在一个分支上完成。

### 1.2 完成标准

不接电脑、不打开网页，拿起设备就能：

1. 按住 BOOT 键或长按鬼火开始说话，Agent 用屏幕文字加语音回答；朗读中再次长按可以打断它；
2. 让它记住偏好、建待办；到点它会亮屏、响铃提醒；
3. 让它写一个场景，比如番茄钟，场景当场装好并打开；
4. 用手势在主界面、设置、场景列表、对话记录之间切换。

网页聊天页同时可用。API Key、Wi-Fi 等配置仍然在管理后台完成。

### 1.3 已定的决策

| 项 | 结论 |
|---|---|
| ASR / TTS | 先接 OpenAI 兼容接口（`/audio/transcriptions`、`/audio/speech`），推荐硅基流动。流式私有协议（百炼、火山、讯飞）在 MVP 之后加，模型配置的多 profile 结构不用改 |
| 开始说话 | 只有按住说话（BOOT 键或长按鬼火，基础 spec 1.9）；点一下鬼火不触发语音，留给以后设计的角色互动用 |
| 唤醒词 | 不在 MVP 里 |
| 对话显示 | 鬼火在上，本轮的 `<say>` 用大字显示，正文细节在下方；结束后鬼火回到中央（基础 spec 1.9"文字输出"） |
| 朗读内容 | LLM 在回复里用 `<say>…</say>` 标记要说的话（第 4.3 节），不用工具调用 |
| 记忆 | Agent 可读写的记忆笔记，加带定时提醒的待办；不做检索和自动总结 |
| 导航 | 按基础 spec 1.9 的空间比喻：右划设置、左划场景列表、下划对话记录；上划颜色预设推迟 |
| 上下文 | 4a 的上下文压缩保留（4a 3.3） |
| 流程 | 只当场修 Critical / Important；Minor 进 `docs/backlog.md`；修复不做复审，由主控直接看 diff；低风险任务批量评审；真机验收用冒烟版 |

### 1.4 组件与分层

可移植层的顺序变为：

`wisp_base → wisp_os → wisp_hal → wisp_core → wisp_net → wisp_voice → wisp_admin → wisp_ui → wisp_scene → wisp_agent → wisp_shell → wisp_app`

同步更新 `tools/check_layering.py`、AGENTS.md 第 3 节和 `docs/architecture.md`。

| 组件 | 状态 | 内容 |
|---|---|---|
| `wisp_core` | 扩充 | `MemoryStore`（第 5.1 节）、`ReminderScheduler`（第 5.2 节） |
| `wisp_voice` | 新增 | `VoiceService`：收音、VAD、ASR、TTS、播放队列；`SayParser`（第 4 节） |
| `wisp_ui` | 扩充 | `WispView` 鬼火渲染控件（第 6.1 节），只接收状态参数 |
| `wisp_agent` | 4a | 按第 3 节裁剪 |
| `wisp_shell` | 新增 | 主界面、设置页、场景列表、对话记录、导航手势、场景内说话浮层；`ConversationController` 串起语音与 Agent（第 6 节） |
| `wisp_app` | 扩充 | 启动时装配以上服务；开机进入主界面，自检界面移到"关于本机 → 硬件诊断" |

`wisp_admin` 排在 `wisp_voice` 之后，以便以后在管理后台测试 ASR 和 TTS。MVP 的管理后台只新增"记忆"页（第 5.3 节）。

### 1.5 一轮语音对话的数据流

1. 用户触发说话。`ConversationController` 让 `VoiceService` 开始收音，并发布 `voice.state = listening`。
2. 说完（VAD 判断或松开）后，录音交给 ASR，得到文字。
3. 文字以 `source = voice` 交给 `AgentService.submit()`，进入 4a 的对话循环。
4. 回复流经过 `SayParser`。
   - `<say>` 里的文字送去 TTS，并在主界面显示为大字；
   - 标记以外的正文进入细节区。
5. TTS 返回 PCM，直接送到音频输出。播放期间发布 `voice.state = speaking` 和音量事件。
6. 鬼火渲染器根据 `agent.state` 与 `voice.state` 切换表情。

| 阶段 | 内容 | 依赖 |
|---|---|---|
| 1 | Agent 核心（裁剪后的 4a），网页聊天可用 | 3b-1 合并到 `feat/agent-core` |
| 1′ | 鬼火渲染器 `WispView`，在单独的工作树 `wisp-wispview` 中并行开发 | 无 |
| 2 | 记忆与提醒 | 1 |
| 3 | 语音链路 | 1 |

| 5 | 联调、冒烟测试、真机试用 | 全部 |

- 唤醒词；流式 ASR 与实时字幕；语音说"确认"；
- 鬼火颜色预设，充电、低电量、打瞌睡等其余表情，场景里嵌入的迷你鬼火控件；
- 4a 的每日 token 预算与用量统计、`ui.check`、截图、模拟输入；

### 3.3 上下文增补

- **固定部分**加入：
  - 回复格式：先用 `<say>…</say>` 写一两句口语结论，再写正文细节。`<say>` 里不用 Markdown、列表和代码。给出示例。
  - 记忆规则：只记长期有用的信息，如称呼、偏好、常住地；不记一次性的事情；存满时自己合并。
- **动态部分**加入：
  - 全部记忆笔记；
  - 当前本地时间与星期；
  - 这条消息的来源。来源为 `voice` 时，要求正文也尽量简短。
- 记忆笔记放在动态部分的最前面，它变化少，这样对前缀缓存影响最小。

### 3.4 `submit()` 的来源

`AgentService::submit(text, source)`，`source` 取值：

- `voice`：语音；
- `device_text`：设备上的输入，预留；
- `web`：网页。

只有 `voice` 来源的这一轮会朗读。每条消息都记录来源，对话记录里语音消息带一个小图标。

### 3.5 事件

- `agent.state` 沿用 4a 3.8 的取值：`idle`、`thinking`、`tool`、`output`、`waiting_confirm`、`error`。
- 新增 `voice.state`，取值：`idle`、`listening`、`transcribing`、`speaking`、`error`。附带字段：
  - `listening` 时带 `level`（0–100），节流到 20 Hz；
  - `speaking` 时同样带 `level`；
  - `error` 时带 `reason`（第 4.6 节）。
- 渲染器的表情按以下优先级决定：

| 优先级 | 条件 | 表情 |
|---|---|---|
| 1 | `voice.state` 为 `listening` | 收听 |
| 2 | `voice.state` 为 `speaking` | 说话 |
| 3 | `agent.state` 为 `thinking`、`tool` 或 `waiting_confirm`，或 `voice.state` 为 `transcribing` | 思考 |
| 4 | 任一事件为 `error` | 出错，约 2 秒后回到待机 |
| 5 | 其余情况 | 待机 |

## 4. 语音链路（`wisp_voice`）

### 4.1 收音

- **格式**：16 kHz、单声道、16 位，取 ES7210 的一路，由 `audio_in` 驱动提供。
  - 缓冲放在 PSRAM（`Mem::Large`），单次最长 30 秒，约 960 KB；到上限自动结束。
- **按住说话**：
  - 适用于 BOOT 键，或长按鬼火；
  - 按住约 300 ms 后开始收音，松开就结束并发送；
  - 按住时上划取消；
  - 按住说话（按键或长按屏幕）完全不跑 VAD：录音满 300 ms 就发送，不足 300 ms 视为误触。
- **点一下鬼火**：MVP 里没有语音作用，留给以后设计的角色互动用（例如摸头）；点击不开始、不结束收音，也不打断朗读。
- **提示**：开始收音时播一声短提示音（复用 `wisp.tone`）。
- **VAD**：`wisp_voice` 里的 VAD 组件和它的点一下收音模式保留为待用代码（当前没有触发入口），基于能量并自适应噪声底，供以后的角色互动或唤醒词复用：
  - 开麦后先丢弃 100 ms（编解码器的 pop 和提示音尾巴），再用前 300 ms 中最安静的一半估计噪声底，开头的瞬态不会抬高它；噪声底下降快、上升慢；
  - 帧能量高于噪声底 + 阈值，视为语音帧；
  - 开始后 5 秒内没有语音，就取消，显示"没听清"；
  - 有语音后连续 800 ms 静音，视为说完；
  - 有效语音不足 300 ms，视为误触，直接丢弃，不发请求。

### 4.2 识别（ASR）

- **请求**：`POST {base_url}/audio/transcriptions`，`multipart/form-data`。
  - `file` 是 WAV（44 字节头 + PCM），上传时从 PSRAM 流式读取，不另外复制一份；
  - `model` 取当前激活的 `asr` 配置；`language` 取其 `options`。
- **结果**：解析返回 JSON 的 `text`。
- **超时**：15 秒。
- **出错**：
  - 结果为空时，显示"没听清"；
  - 429 或 5xx 时，重试 1 次。
- **Key**：经 `ModelProfileService::active_for_request(asr)` 取得，只放进请求头，规则同 4a 3.6。
- **日志**：不记录录音和识别出的文字，只记时长、字节数、耗时和状态码。

### 4.3 `<say>` 解析（`SayParser`）

- 输入是回复文字的增量流，输出两路事件：
  - `say_text(delta)`：标记内的文字；
  - `body_text(delta)`：标记外的文字。
- 增量在任意位置切开都能正确识别，包括切在 `<sa` | `y>` 这样的标记中间。
- 一轮可以有多段 `<say>`。工具调用之间的文字也会解析，这样多步任务中途可以说话。
- 标记不闭合时，这一轮结束时把剩下的文字当作 say 处理。
- 没有任何 `<say>` 时，这一轮结束时取正文的第一句作为 say，只用于朗读，屏幕照常显示正文。
- 存入 ConversationStore 的是模型的原始回复（包含标记），以便上下文保持原样；网页和设备显示时再去掉标记。

### 4.4 朗读（TTS）

- **分句**：say 文字按 `。！？!?；;` 和换行切成句子。
  - 第一句一完整就发出合成请求；
  - 播放第 n 句的同时，合成第 n+1 句；
  - 每轮朗读最多 200 字，超出部分只显示不读。
- **请求**：`POST {base_url}/audio/speech`，请求体为：
  - `model`、`input`、`voice`；
  - `response_format: "pcm"`；
  - `sample_rate` 取配置的值，默认 24000；
  - `speed` 可选。
- **超时**：15 秒是允许没有新音频到达的时间，不是整句朗读必须在 15 秒内读完；请求的截止时间随句子长度增长。
- **播放**：
  - 返回的 PCM 写入 PSRAM 环形缓冲（`Mem::Large`，约 2 秒）；
  - 由播放任务送到 `audio_out`，按 `sample_rate` 设置 I2S；
  - 不需要解码器。
- **何时朗读**：只有 `source = voice` 且设置 `voice/tts_mute` 为 false 时才朗读。不朗读时，say 文字照样显示。
- **打断**：
  - 朗读时按住说话（BOOT 键或长按鬼火），就停止朗读，清空队列，取消进行中的合成请求，并开始新一轮收音；
  - 如果这时 Agent 这一轮还没结束，先中止这一轮（4a 3.4），再开始收音；
  - 朗读时点一下鬼火没有语音作用，不会停止朗读。
- **音量**：朗读使用 `audio/volume`。

### 4.5 线程、内存与电源

- **任务**：`wisp.voice` 负责收音、VAD、ASR 与 TTS 的请求，声明 `flash_access = false`，栈放在 PSRAM。
  - 播放复用已有的音频输出路径，优先级高于 UI 任务；
  - 栈大小按 `mem` 实测 high-water mark 定。
- **大缓冲**：全部用 `Mem::Large`。内部 RAM 只放 I2S 的 DMA 缓冲（`Mem::Dma`）。
- **TLS**：同一时间只有一个 TLS 连接。ASR、LLM、TTS 的请求按顺序发出，下一句的 TTS 合成与 LLM 流式请求不重叠。
  - 如果 LLM 还在流式输出，TTS 请求排队等它结束。
  - 第一句 say 通常在回复开头就完成，此时 LLM 流还在进行。为了不让朗读等到整个回复结束，这一句允许和 LLM 流并发，最多同时 2 个 TLS 连接。
  - 第 3 阶段完成后上真机，在这种并发情况下测一次 `mem`。如果最坏情况下内部 RAM 低于预算下限，就改回严格串行，并把这条记进 backlog。
- **唤醒锁**：一轮语音对话期间（从开始收音到朗读结束）持有三把锁，持有者都是 `system.voice`：
  - `screen`：保持亮屏；
  - `network`；
  - `cpu`。
  - 3b-1 已规定场景的 `screen` 锁不发 30 分钟提醒，系统的锁照常提醒；一轮对话远短于 30 分钟。

### 4.6 出错

- `voice.state = error`，`reason` 取值：
  - `no_asr_profile`、`no_tts_profile`；
  - `offline`；
  - `asr_failed`、`tts_failed`；
  - `mic_unavailable`。
- 主界面在鬼火下方用一句话说明原因。例如"还没配置语音识别，请在管理后台的模型页设置"，并附上管理后台地址。
- TTS 失败只影响朗读，文字照常显示。

## 5. 记忆与提醒（`wisp_core`）

### 5.1 `MemoryStore`

- **存储**：System 区 `memory/notes.json`，经 `StorageManager::write_atomic` 写入；只在 `wisp.fs` 上执行（flash-thread spec 2.1）。
  - 格式：`{"version":1,"notes":[{"id","text","updated"}]}`；
  - `id` 为递增整数。
- **容量**：最多 64 条，每条最多 200 个字符。超出时：
  - 条数满了，返回 `memory_full`；
  - 单条太长，返回 `too_long`。
- **线程安全**：Agent 线程与管理后台的 HTTP 线程都会调用，经 `StorageWorker::submit()`/`run_sync()` 把读写排到 `wisp.fs`，调用方不直接碰 flash（AGENTS.md 第 5 节）。
- **事件**：每次修改发布 `memory.changed {count}`，不带内容。
- **日志**：不记录笔记内容。
- **恢复出厂**：一并清除。

### 5.2 `ReminderScheduler`

- **存储**：System 区 `todo/todos.json`，经 `write_atomic` 写入；和 `MemoryStore` 一样只在 `wisp.fs` 上执行，工具调用（`todo.*`）经 `submit()`/`run_sync()` 把读写排到 `wisp.fs`。字段：
  - `id`、`title`（最多 100 字）、`done`、`created`；
  - `due`：UTC 秒，可选；
  - `repeat`：`none`、`daily`，或 `weekly` 加星期掩码；
  - `snooze_until`：可选。
- **容量**：最多 200 条，满了返回 `todo_full`。已完成的待办不会被自动删除，只能由 Agent 或用户删除。
- **时区**：本地时间按已有设置 `utc_offset` 换算，与 3b-1 一致，是固定偏移，不做夏令时。
- **时钟未设置时**：带 `due` 的 `add` 和 `update` 返回 `clock_not_set`；不带时间的待办照常添加。
- **定时**：
  - 只为最近的一个到期时间设一个 `os` 定时器，增删改后重新计算；
  - 浅睡和深度待机中，这个定时器也能唤醒设备；
  - 定时器回调只投递消息，实际处理在 `wisp.fs` 上完成。处理过程会写 flash。
- **到点时**：发一条系统通知。
  - 内容：`source = "system.reminder"`，`id = "todo-<id>"`，标题为待办标题，`sound = "alarm"`，`wake = true`；
  - 复用 3b-1 的通知服务，所以会亮屏、响铃、弹横幅；
  - 通知带两个操作："完成"（`todo.done`）和"10 分钟后"（设 `snooze_until`）；
  - 重复的待办到点后计算下一次时间，不标记完成。
- **错过的提醒**：开机后（或时钟第一次设置后），把 `due` 已过、未完成、未处理过的待办合并成一条通知"错过 N 个提醒"，点开显示标题列表。每条只报一次，用 `notified_at` 字段记录。
- **事件**：每次修改发布 `todo.changed {count}`。

### 5.3 管理后台"记忆"页

- **REST**，都需要令牌，删除操作还要带 `X-Wisp`（连接 spec 6.3）：
  - `GET /memory`、`DELETE /memory/{id}`；
  - `GET /todos`、`DELETE /todos/{id}`。
- **网页**：新增"记忆"页，分"记忆笔记"和"待办"两栏，每条都有删除按钮，删除前用 `confirmDialog` 确认。界面提供中、日、英三语。

## 6. 系统外壳与鬼火主界面

### 6.1 鬼火渲染器 `WispView`（`wisp_ui`）

极简描边风格（2026-11-06 用户决定，取代基础 spec 1.9 的亮度图加调色板方案）：减少计算量和渲染量，并能适配单色屏、墨水屏。

- **形状**：一条闭合描边，水滴形身体加顶部 2–3 个火苗尖一笔连成；身体内部不填色，没有光晕和渐变。线宽约为鬼火高度的 1/40，不小于 2 px。
- **运动**：轮廓控制点叠加 2–3 层不同频率的正弦扰动（顶部大、底部小）；火苗尖挂在弹簧阻尼模型上。
- **眼睛**：两个较大的实心椭圆，是表情的主要载体；眯眼"> <"用短线。鬼火没有嘴。
- **火星**：彩色屏上最多 6 个小圆点；单色屏与墨水屏上关闭。
- **颜色**：彩色屏只用一种主题色（幽蓝）；单色屏为白色，墨水屏为黑色。
- **绘制**：在 LVGL 绘制事件里直接画折线、短线和小椭圆，只标记鬼火外接框为脏区，不用离屏帧缓冲。
- **计算**：定点数和预计算查找表，每帧不做浮点超越函数运算，不分配内存。
- **尺寸**：按 `hal::safe_rect()` 的短边比例计算。
- **按屏幕类型**（Display caps `panel`）：
  - AMOLED / LCD：抗锯齿，15–30 fps，有火星；
  - 单色屏：不抗锯齿，约 10 fps，无火星；
  - 墨水屏：不抗锯齿，只在表情切换时刷新一次，不做连续动画，无火星。

接口：

```cpp
namespace wisp::ui {
enum class WispMood : uint8_t { Idle, Listening, Thinking, Speaking, Error };
class WispView {
public:
    static WispView* create(lv_obj_t* parent, int size_px);  // UI thread only
    void set_mood(WispMood mood);        // smooth transition
    void set_level(uint8_t level);       // 0..100, mic or TTS loudness
    void set_busy(bool fast);            // faster particles while a tool runs
    void set_paused(bool paused);        // screen off: no frames
};
}
```

- **五种表情**，每种是一组参数，切换时平滑插值：
  - 待机：呼吸起伏、眨眼、张望，整体缓慢漂浮，用来防烧屏；
  - 收听：轮廓变高、眼睛变大，火苗随 `level` 跳动；
  - 思考：眼睛看向右上方，火星环绕（无火星的屏幕上只看眼睛）；`set_busy(true)` 时摆动加快；
  - 说话：没有嘴，眼睛随 `level` 上下压扁回弹，身体与火苗尖随 `level` 轻轻弹动；
  - 出错：眼睛变成"> <"，身体抖一下。表情只靠形状区分，不依赖颜色。
- **帧率**：动作多时 30 fps，平静时 15 fps，熄屏时停止。
- **性能基准**：记入 `WISP_PERF`，增加 `wisp_fps` 与 `wisp_ms` 字段。
  - 真机上动作多时不低于 20 fps；
  - 说话时渲染器降到 15 fps，给播放让出 CPU。
- **开发方式**：渲染器不依赖 Agent 和语音，在 `wisp-wispview` 工作树中独立开发。模拟器加 `--wisp-demo` 参数，循环演示五种表情。

### 6.2 主界面

主界面是一个原生 C++ 屏幕，不是 Lua 场景（基础 spec 1.9 定位）。

- **平时**：鬼火水平居中，中心在安全区高度约 42% 处（略高于正中），大小约为安全区短边的 55%。
- **一轮对话中**：
  - 鬼火缩小到约 28%，移到上方；
  - 鬼火上方用小字显示识别出的原话（`muted` 颜色，最多 2 行）；
  - 鬼火下方用大字显示 `<say>` 文字，用矢量字体，约 28 px，自动换行；
  - 再往下用 16 px 正文显示正文细节，区域可以滚动。正文只做轻量的 Markdown 处理：去掉 `**`，列表项前加 `•`，代码块用等宽字体。
- **Agent 的步骤**（activity list，活动列表）：一轮里调用过工具时，屏幕显示 Agent 在做什么。
  - 数据：`ConversationController` 在 `TurnView` 里保留最近 4 步（`TurnStep`：文字和状态 Running/Done/Failed）、本轮总步数和开始/结束时间。Agent 的 ToolPrep 事件（模型还在流式写工具调用，见 4a spec 3.8）先建一个进行中的步骤（"写入文件 · 3.2 KB"），ToolStart 把它换成真正的调用，ToolEnd 标记完成或失败；到下一次思考或轮次结束还没有 ToolStart 的进行中步骤（调用被跳过或回复出错）直接去掉，不计入总步数；工具之后再次思考时显示一个临时的"思考中"步骤，不保存。
  - 文字：`wisp_shell` 的 `activity_label(tool, args_summary)` 按字符串表给每个已注册工具一个中/日/英友好名称，并从参数摘要里宽松地取出 `path`/`name`/`title`/`id` 中的第一个作为对象（摘要可能被截断，不是合法 JSON）；未知工具显示"调用 <tool>"。除这一个短对象外不显示任何参数内容：文件内容、记忆文字、设置值可能是隐私，设置类工具不显示对象，设置值可能是密钥，永远不显示。
  - 显示：一轮进行中、还没有 `<say>`/正文时，步骤列表占用鬼火下方的列区域，每步一行，按该行的 `row_span()` 用"…"截断，行首是状态符号（进行中为脉动的点，完成 ✓，失败 ×；源字体没有 ✗，用 ×）。列表下方一行 `muted` 小字"第 N 步 · 42 秒"，每秒刷新。文字开始输出后，列表收起成这一行，作为列的第一行随列滚动；一轮结束后改为"用了 N 步 · 1 分 12 秒"（只在 N > 0 时显示）。没有步骤的轮次两者都不显示，排版与原来相同。
  - 设备确认（WaitingConfirm）照旧。
- **结束后**：一轮结束约 15 秒内没有新的交互，文字淡出，鬼火回到平时的位置。用户滚动细节区会重新计时。
- **网页发起的对话**：主界面同样显示，只是不朗读。
- **排版**：全部按 `hal::safe_rect()` 与 `row_span()` 排版（3a spec 5.6）。滚动到两端时，首尾内容必须完整落在可见区内。

### 6.3 导航

| 在主界面上 | 结果 |
|---|---|
| 右划 | 设置页，从左边滑入 |
| 左划 | 场景列表，从右边滑入 |
| 起点不在顶边判定区的下划 | 对话记录，从上方滑入 |
| 起点在顶边 16 px 判定区内的下划 | 通知面板（3b-1 spec 5.6，不变） |
| 长按鬼火 | 按住说话；朗读中长按会打断它 |
| 点一下鬼火 | 没有语音作用，留给以后设计的角色互动用 |

- **跟手**：页面跟着手指走，不是划完才切换。手指沿某个有目标页的方向移动超过 10 px（与 LVGL 判定滚动的距离相同）后开始拖动：目标页在这一刻建好，当前页和目标页沿这条轴与手指 1:1 移动，另一方向的位移忽略，拖动距离限制在 0 到屏幕宽（或高）之间。
- **松手**：拖过屏幕宽（或高）的 1/3，或者松手前约 50 ms 内手指沿拖动方向的速度不低于 0.4 px/ms，就完成切换；否则弹回，目标子页像平常离开时一样销毁。剩下的距离用缓出动画走完，时长按剩余比例缩放，最长 220 ms。按压被系统层拿走（`PRESS_LOST`）时弹回。动画结束时才切换"当前屏幕"，所以场景运行时判断哪个屏幕在前面时不受动画影响；动画期间有别的屏幕（例如场景）到了前面，就按弹回处理。
- **不开始拖动**：按在自己用拖动的控件上（滑块）；手指下的可滚动区域还能朝这个方向滚（例如对话记录不在底端时上划是滚动列表，到了底端才是返回；主界面的细节区同理）；鬼火正在按住说话。程序触发的切换（硬件诊断、对话浮层点回主界面等）直接切换，不播放动画，并先结束进行中的拖动。
- **返回**：子页里朝反方向拖就回到主界面。子页本身可以滚动的方向不受影响：例如场景列表是上下滚动，返回用右划。
- **场景里**：从左边缘右划返回主界面（3a / 3b-1 已有）。
- **按键**：亮屏时，BOOT 键在任何页面都表示按住说话。

### 6.4 子页

- **对话记录**：
  - 从 ConversationStore 读取，最新的一轮在最下方，打开时滚动到底部；
  - 每一轮显示用户消息（语音消息带小图标）、`<say>` 文字，以及折叠起来的正文，点开展开；
  - 只加载最近 50 轮，往上滚动到顶部再分批加载；
  - 底部有"新对话"按钮，确认后归档当前对话（4a 3.5）。
- **场景列表**：
  - 卡片网格，每张卡片显示 `scene.json` 的图标与名称，按最近使用排序；
  - 后台运行中的场景带标记，不可用的场景（例如 SD 卡未插入）变灰；
  - 点一下就打开；
  - 长按弹出"删除"，经系统确认框确认，可以勾选"同时删除数据"；
  - 列表为空时显示一句提示："还没有场景，试试对我说'做一个番茄钟'"。
  - 页面立刻出现，不等存储：第一次打开时先显示加载中的占位卡片（只画一屏、全部落在安全区内），之后再打开时先显示上一次的列表；存储读完后原地补齐或刷新（列表没变就什么都不重建），保持滚动位置和长按卡片。图标在后台逐个解码，先显示名称首字，解码完再换上；
  - 每次打开记一行耗时日志 `shell: scenes ms_list= ms_icons= ms_build= n= icons_decoded= cached=`（列出场景、解码新图标、UI 线程建卡片各花多少毫秒；`cached=1` 表示这次列表没有读存储），用于在真机上找出慢在哪里。
- **设置页**：
  - 亮度、音量（滑条）；
  - 自动熄屏时间；
  - 静音朗读；
  - Wi-Fi：显示状态，点进去进入子项目 2 已有的设备端配网流程；
  - 关于本机：固件版本、IP 与管理后台地址、配对入口、"硬件诊断"（进入原来的自检界面）。
  - 每一项都直接调用 `SystemSettings` 等服务（AGENTS.md 第 3 节）。

### 6.5 场景里说话

- 场景在前台时按住 BOOT 键，底部弹出系统浮层：一个脉动光点加音量条，位置按安全区计算。
- 松开后浮层显示"思考中…"（有正在进行的步骤时显示该步骤的文字，见 6.2），回复的 `<say>` 文字在浮层里显示约 5 秒，同时朗读。完整内容进入对话记录。
- 浮层显示期间，点一下浮层就打开主界面，看完整回复。
- Agent 打开或安装别的场景时，前台直接切过去。

### 6.6 开机

- 开机后进入主界面。
- 自检界面不再是首页，只在"关于本机 → 硬件诊断"中打开。3b-1 中它对 IMU 的订阅规则不变（场景盖住它时退订）。
- 第一次开机时，还没配置 `llm` 配置或 Wi-Fi，主界面在鬼火下方显示一句引导文字和管理后台地址；点一下鬼火也会说明这一点，不发请求。

## 7. 测试、验收与风险

### 7.1 自动测试

- **TDD**：所有服务都先在模拟器里测通。
- **假服务**：FakeLlm、FakeAsr、FakeTts 都是进程内的 `HttpClient`。按脚本返回固定的回复、工具调用、识别结果和 PCM。
- **单元测试**：
  - VAD：合成的静音、语音、噪声音频；开始超时；误触丢弃；
  - `SayParser`：标记切在增量之间、多段标记、标记不闭合、没有标记、标记出现在工具调用之间；
  - ASR 与 TTS 客户端：multipart 格式；PCM 的流式接收；取消；错误码；
  - `MemoryStore` 与 `ReminderScheduler`：容量上限；时区；重复规则；推迟；开机补报错过的提醒；时钟未设置；
  - `WispView`：固定随机种子下确定帧的哈希；表情插值；脏区不超出外接框；暂停后不再出帧；
  - 外壳：四个方向的手势判定；与顶边下划及返回手势的区分。
- **冒烟测试**（`tests/smoke/`）：
  - 语音一轮：`debug voice-text "明天早上8点提醒我带伞"` → Agent 调用 `todo.add` → 回复带 `<say>` → 假 TTS 播放 → 日志里依次出现各个状态；
  - 写场景：让 Agent 做一个计数器场景 → 安装并打开 → 返回主界面；
  - 提醒：建一个 1 分钟后的提醒 → 拨快时钟 → 出现横幅 → 点"完成"；
  - 导航：三种屏幕形状下走一遍四个方向，截图保存主界面待机、对话中、对话记录、场景列表、设置页。
- **模拟器调试命令**（只在 `WISP_SIM_DEBUG_COMMANDS` 下编译）：
  - `debug voice-text <文字>`：跳过录音与 ASR，直接把文字作为一句语音提问；
  - `debug clock-advance <秒>`。

### 7.2 真机试用（冒烟版，用户配合）

需要准备：一个 OpenAI 兼容的 ASR/TTS Key（推荐硅基流动）、DeepSeek 的 Key，以及能联网的 Wi-Fi。

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 开机进入主界面 | 鬼火待机动画流畅；`WISP_PERF` 的 `wisp_fps` 平静时约 15，动作多时不低于 20 |
| 2 | 两种说话方式 | BOOT 键按住、长按鬼火，都能完成一轮对话 |
| 3 | 首句延迟 | 从说完到听到第一句朗读，测 5 次取中位数，目标 4 秒以内（记录实测值） |
| 4 | 打断 | 朗读时按住说话（BOOT 键或长按鬼火）能打断朗读并开始新一轮 |
| 5 | 记忆 | 说"记住我叫……"，重启后再问，它仍然记得 |
| 6 | 提醒 | 建一个 2 分钟后的提醒，熄屏等待，到点亮屏、响铃、弹横幅；"完成"和"10 分钟后"都可用 |
| 7 | 写场景 | 语音说"做一个番茄钟"，场景装好并打开，可以正常使用 |
| 8 | 导航与设置 | 四个方向的手势可用，设置页各项生效 |
| 9 | 确认 | 语音要求删除场景时，设备弹出确认框；拒绝后场景还在 |
| 10 | 内存 | 第 4.5 节的并发情况下用 `mem` 查看，内部 RAM 不低于 `ram_budget.hpp` 的下限 |

其余检查项进 `docs/backlog.md`，日常使用中遇到问题再处理。

### 7.3 风险与对策

| 风险 | 对策 |
